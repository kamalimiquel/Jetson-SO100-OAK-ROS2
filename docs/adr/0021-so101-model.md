# ADR-0021: the arm is an SO-101 — model the right robot

- Status: Accepted
- Date: 2026-11-09
- Decided by: observed behaviour (MuJoCo matched the hardware, RViz did not)

## Context

RViz kept drawing poses that did not match the physical arm while the MuJoCo twin did.
Both consume the same `/joint_states`, so the values were never in question. The twin's
console showed the model it loads: `mujoco_menagerie/robotstudio_so101/scene.xml`.

The URDF in RViz had been generated from the **SO-100** Menagerie model (`trs_so_arm100`):
different link frames, different joint axes (0 0 1 vs 0 1 0 / 1 0 0), different link
lengths. RViz was drawing a different robot, and every hand-eye attempt was solving
against the wrong kinematics — which is why the residual never dropped below ~140 mm
no matter the solver, the signs, the intrinsics or the capture hygiene.

## Decision

Drive RViz and every consumer of forward kinematics from a URDF **generated from the
SO-101 MJCF** (`robotstudio_so101/so101.xml`), not hand-written and not derived from the
SO-100:

- `tools/mjcf_so101_to_urdf.py` converts bodies → links and joints → revolute joints
  (origin from `pos`/`quat`, MJCF quats are **w x y z**; `axis` and `range` taken as-is;
  bodies without a joint become `fixed` joints, otherwise urdfdom rejects the model).
- 17 STL assemblies are converted to OBJ (`docker/web/so101/meshes`): RViz's STL loader
  fails silently on these binary files while OBJ loads fine.
- Joint names in the SO-101 model are already LeRobot's, so `/joint_states` maps directly.
- `tools/handeye_capture.py` now computes FK **from the URDF file**, never from a
  hand-copied chain, so this class of mistake cannot come back.

## Consequences

- Verified: FK from the generated URDF equals the MJCF chain to the millimetre at zero
  (`jaw = [0.317, 0.018, 0.255]`) and at arbitrary poses.
- RViz now reports `Global Status: Ok` and draws the arm that exists on the bench.
- The hand-eye calibration has to be re-run from scratch: the previous datasets were
  solved against the wrong robot and are only useful as a record of the diagnostics.
- Anything that hard-codes SO-100 link geometry must be revisited (the twin already uses
  SO-101, the teleop works in joint space and is unaffected).
