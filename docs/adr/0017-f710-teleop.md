# ADR-0017: F710 teleoperation from Windows

- Status: Accepted
- Date: 2026-11-07
- Decided by: user (alternative 1 of 3, after a feasibility question)

## Context

The Logitech F710 on the Windows 11 PC drives the arm over the LAN. The arm exposes a joint-space API (ADR-0009). ROS2 Humble has official Windows binaries, so a native C++ client is viable without virtualization.

## Alternatives

1. **Native Windows C++ client (rclcpp + SDL2)** publishing joint targets → joint-bridge node on the Jetson. Pros: pure C++, no virtualization, direct gamepad read, fits the joint-space API. Cons: ROS2 Humble install + VS Build Tools on Windows; firewall/multicast setup.
2. **WSL2 + usbipd-win + `joy_linux`** — Pros: standard Linux stack. Cons: fragile USB passthrough and the WSL2 networking/DDS pain.
3. **phosphobot web teleop** — Pros: already exists. Cons: being replaced by LeRobot (ADR-0006); bypasses ROS2 entirely.

## Decision

**Native Windows C++ client**: rclcpp + SDL2 reading the F710, publishing joint targets to the Jetson's control container over DDS.

## Consequences

- Windows needs ROS2 Humble (binary install, runtime only) + Visual Studio Build Tools + SDL2 dev — one-time setup, documented in the repo when implemented.
- The client publishes joint targets (matches ADR-0009); joystick deltas map to joint deltas. Cartesian pose sending stays possible later with an IK node on the Jetson.
- Windows Firewall must allow ROS2 traffic (UDP multicast) — a known silent-failure point; static FastDDS peers as fallback (ADR-0002).
- Control modes: joint step mode, Cartesian-feel mode (deltas converted to joint increments), record/replay trajectories (ADR-0012).
